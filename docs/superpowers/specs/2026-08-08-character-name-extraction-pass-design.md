# 人物名列挙パスの追加 — 設計

日付: 2026-08-08

## 問題

`summarize` コマンドの結果で登場人物の抽出漏れが多い。

原因は、1 回の LLM コールに「前回要約との統合 + 約 50 ページ分の本文からの人物抽出 +
あらすじ更新 + シーン・モチーフ抽出」を同時にやらせている構造にある。モデルの注意は
物語の流れの更新に向かい、端役や一言だけの言及の列挙が疎かになる。プロンプトの
「漏らさず全て」という指示だけではこの注意配分は変わらない。

## 方針

チャンクごとに、人物名の列挙だけを行う軽量な LLM コールを要約コールの前段に追加する。
列挙結果の名前リストを要約コールの user message に「必ず characters に含めること」という
チェックリストとして埋め込む。

- 列挙コールの入力はチャンク本文のみ(前回要約 JSON は含めない)。出力は名前のリストのみ。
- 列挙タスクを単独にすることで網羅列挙の再現率を上げる。
- 列挙コールは要約とは別のモデルを指定でき、デフォルトは安価な `gpt-5-nano` とする。

## 変更内容

### `types.py`

```python
class CharacterNames(BaseModel):
    """チャンクに登場する人物名の一覧"""

    names: list[str]  # 端役や一度きりの言及も含む。名前が不明な人物は呼称で表す
```

### `prompts.py`

- `ExtractCharacterNamesSystem`: 列挙用の system プロンプト。
  「このチャンクに登場・言及される人物を全員列挙。端役、名前のない人物(呼称で表す)、
  一度きりの言及も含む」という趣旨。
- 要約コール用に、名前チェックリストを埋め込むテンプレート文言を追加。

### `summarizer/__init__.py`

- `EXTRACT_MODEL = "gpt-5-nano"` を追加。
- `extract_character_names(chunk_text, *, model) -> tuple[list[str], Cost]` を追加。
- `summarize_page(...)` に `character_names: list[str] | None = None` を追加し、
  リストが空でないときのみ user message にチェックリスト節を挿入する。
  message 組み立ては純粋関数に切り出してテスト可能にする。
- `summarize(chunks, *, model, extract_model)` は各チャンクで列挙 → 要約の順にコールし、
  `(chunk, summary, summary_cost, extract_cost)` を yield する。
  列挙コストは別モデルで課金されるため要約コストとは分けて返す。

### `__init__.py` (CLI)

- `--extract-model` オプションを追加(デフォルト `gpt-5-nano`)。
- 列挙コスト用のバケットを追加し、`_log_api_costs` を
  Extraction / Summaries / Overview / Combined の 4 区分に拡張する。

## エラー処理

- 列挙結果が空リストでもエラーにしない(チェックリスト節を省くだけ)。
- API エラーは既存コードと同様に伝播させる(新たなリトライ等は導入しない)。

## テスト

- message 組み立て関数: チェックリスト有り / 無し(None・空リスト)の両方を検証する。
- コスト集計: 列挙バケットが別モデルの単価で計上されることを検証する。
- LLM コール自体はモック不要の範囲でテストしない(既存方針を踏襲)。

## コストへの影響

増分はほぼ「チャンク本文を列挙コールにもう 1 回入力する分」のみ。
`gpt-5-nano` の入力単価は gpt-4o-mini の 1/3 なので、全体コストの増加は小さい。
